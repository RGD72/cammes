## Story

**As a** lojista-cliente,
**I want** fazer download de um PDF profissional do meu pedido com cabeçalho, tabela tabular e total,
**so that** eu tenha um documento arquivável e compartilhável (com a marca, com minha equipe).

## Acceptance Criteria

1. PDF gerado server-side via `@react-pdf/renderer` em API Route `GET /api/orders/[id]/pdf` com `export const runtime = 'nodejs'` (não Edge-compat).
2. Layout do PDF: cabeçalho com nome da marca (e logo, se `brand.logo_url` preenchido), nome do cliente, número do pedido (`order_number`), data/hora formatada (`dd/MM/yyyy HH:mm`), e rodapé com marca d'água sutil "CAMMES" centralizado.
3. Tabela completa com as 8 colunas obrigatórias na ordem exata: REFERÊNCIA, DESCRIÇÃO DO PRODUTO, COR, TAMANHO, QUANTIDADE, NOME DO CLIENTE, VALOR DA PEÇA, VALOR TOTAL — com quebra de página automática quando os itens excedem a altura da página.
4. Linha de "Total Geral" em destaque ao final da tabela (fundo cinza, fonte negrito).
5. PDF gerado é armazenado em Supabase Storage no bucket privado `orders`, caminho `${orderId}.pdf`; campo `orders.pdf_path` é atualizado para `${orderId}.pdf` após upload.
6. API Route retorna `302 redirect` para signed URL do Storage com TTL de 3600s (1h); na resposta, o header `Content-Disposition: attachment; filename="pedido-{order_number}.pdf"` permite download direto.
7. Botão "Baixar PDF" em `/orders/{id}/success` e em `/orders/{id}` passa a ser habilitado e link aponta para `/api/orders/{id}/pdf`; ao clicar, o browser inicia o download do PDF.
8. Se o PDF já foi gerado anteriormente (`orders.pdf_path` não-nulo), a API Route pula a geração e serve nova signed URL a partir do arquivo existente no Storage (sem re-gerar).
9. NFR5: geração end-to-end (primeira chamada) deve completar em <5s p95 para pedidos com até 50 itens.
10. Acesso restrito: apenas o `customer_user_id` do pedido OU admin da marca pode chamar a API Route; outros retornam 403.

### @react-pdf/renderer — Uso Correto

[Source: architecture.md §3.1 — `@react-pdf/renderer` 4.0.x]
- Importar de `@react-pdf/renderer` (não `react-pdf`)
- Para gerar `Buffer` server-side: `import { renderToBuffer } from '@react-pdf/renderer'`
- Componente `.tsx` com primitivos próprios: `Document`, `Page`, `View`, `Text`, `Image` — **NÃO** elementos HTML
- `StyleSheet.create({})` para estilos (não Tailwind — `@react-pdf/renderer` tem CSS próprio subset)
- `export const runtime = 'nodejs'` OBRIGATÓRIO na API Route (não funciona em Edge runtime)
- `pdf-lib` já instalado NÃO é usado aqui — é biblioteca diferente; não confundir

### Storage — Bucket e Upload

[Source: architecture.md §2.2, §3.1 File Storage]
- Bucket: `orders` (private, `public: false`)
- Path no bucket: `${orderId}.pdf` (sem subpasta — o bucket já isola por tipo)
- Upload via admin client (service role): `adminClient.storage.from('orders').upload(path, buffer, { contentType: 'application/pdf', upsert: true })`
- Signed URL via admin client: `adminClient.storage.from('orders').createSignedUrl(path, 3600)`
- Bucket criado via migration SQL: `INSERT INTO storage.buckets (id, name, public) VALUES ('orders', 'orders', false) ON CONFLICT (id) DO NOTHING;`

### API Route — Auth Guard para Admin

[Source: architecture.md §4.8, §5.2 /api/orders/{orderId}/pdf]
- Cliente: verificar `order.customer_user_id === user.id`
- Admin: verificar `brands.owner_admin_id === user.id` onde `brands.id = order.brand_id`
  - Query: `adminClient.from('brands').select('owner_admin_id').eq('id', order.brand_id).single()`
- Se nenhum dos dois: retornar `NextResponse.json({ error: 'Forbidden' }, { status: 403 })`

### Redirect vs JSON

[Source: architecture.md §5.2 — spec original retorna JSON { signedUrl, expiresAt }]
- A spec original define `GET /api/orders/{orderId}/pdf → { signedUrl, expiresAt }` (JSON)
- Para download direto sem JavaScript: pode-se retornar `NextResponse.redirect(signedUrl, 302)`
- **Decisão de implementação**: retornar redirect 302 para simplificar (botão `<a href>` funciona sem JS)
- Alternativa (se tests exigirem JSON): retornar `{ signedUrl, expiresAt }` e usar `<a>` client-side
- Documentar decisão no Dev Agent Record
