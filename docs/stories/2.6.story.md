## Story

**As a** admin-distribuidor,
**I want** poder re-disparar uma extração que falhou ou re-processar um catálogo, sem duplicar produtos e sem perder configurações,
**so that** falhas pontuais do LLM via OpenRouter não me forcem a refazer trabalho de revisão.

## Acceptance Criteria

1. Migration adiciona valor `superseded` ao enum `extraction_status`; Server Action `retriggerExtraction(catalogId, brandId)` (a) verifica que o usuário autenticado é admin e dono da marca (`brands.owner_admin_id = auth.uid()`), (b) busca o job ativo mais recente do catálogo, (c) atualiza seu status para `superseded`, (d) deleta produtos com `extraction_job_id = jobAnterior AND status = 'extracted'` (preserva `approved` e `hidden`), (e) cria novo `extraction_jobs` e dispara a Edge Function, (f) atualiza `catalogs.status` para `processing`.
2. A Edge Function `extract-catalog` é idempotente por job: antes de inserir cada produto, verifica se já existe produto com mesmo `(extraction_job_id, source_page, reference)` usando `INSERT ... ON CONFLICT DO NOTHING`; falhas de rede em páginas já processadas não geram duplicatas.
3. Quando o status de `extraction_jobs` chega a `failed` (após esgotamento de retries da Story 2.4), a tela `/admin/brands/{id}/extraction/{jobId}` exibe um banner de erro claro com a `error_message` do job e botão "Tentar novamente" que invoca `retriggerExtraction`; a tela de detalhe da marca `/admin/brands/{id}` exibe badge de alerta quando o último job está em `failed`.
4. `docs/architecture/extraction-failure-modes.md` documenta quatro cenários: timeout da Edge Function, chave OpenRouter inválida, PDF corrompido, JSON inválido retornado pelo LLM — e para cada um: comportamento atual do pipeline, mensagem de erro esperada em `error_message`, e como o admin deve proceder.
5. Testes unitários para `retriggerExtraction`: (a) job anterior é marcado `superseded`, (b) produtos `extracted` são removidos e `approved`/`hidden` preservados, (c) novo job é criado com status `queued`, (d) erro se não há job ativo para o catálogo.
6. Migration aplicada sem erros via `supabase db reset` (`ALTER TYPE ... ADD VALUE IF NOT EXISTS`).

### Migration: Enum `extraction_status`

PostgreSQL não permite remover valores de enum, mas permite adicionar com `ADD VALUE IF NOT EXISTS`:

```sql
-- supabase/migrations/20260522000005_extraction_superseded_status.sql
ALTER TYPE public.extraction_status ADD VALUE IF NOT EXISTS 'superseded' AFTER 'failed';
```

**Nota:** `ADD VALUE IF NOT EXISTS` requer PostgreSQL 9.3+ e não precisa de transação explícita. Supabase local usa PostgreSQL 15+ — seguro.

### Idempotência via Constraint Única

Para o AC 2, a abordagem mais robusta é um unique constraint composto:

```sql
-- Adicionar à migration 20260522000005 ou nova migration
ALTER TABLE public.products
  ADD CONSTRAINT products_job_page_ref_unique
  UNIQUE (extraction_job_id, source_page, reference);
```

Então na Edge Function, substituir INSERT simples por:

```sql
INSERT INTO products (extraction_job_id, brand_id, catalog_id, ...)
VALUES (...)
ON CONFLICT (extraction_job_id, source_page, reference) DO NOTHING;
```

**Cuidado:** `reference` pode ser `NULL` — NULL ≠ NULL no PostgreSQL, então um UNIQUE constraint simples não previne duplicatas quando reference é nulo. Solução: usar **expression index parcial** (`WHERE reference IS NOT NULL`) para deduplicar produtos com referência, e aceitar que produtos sem referência não são deduplicados por este índice (raridade — se o LLM não extrai reference, o produto provavelmente é fragmentado). Não usar `COALESCE(reference, id::text)` — `id` é gerado pelo banco no INSERT e não está disponível como expressão de conflito. A abordagem correta é:
```sql
-- Índice parcial: deduplicação apenas quando reference != NULL
CREATE UNIQUE INDEX IF NOT EXISTS idx_products_job_page_ref
  ON public.products(extraction_job_id, source_page, reference)
  WHERE reference IS NOT NULL;
```
No Supabase JS client, usar `.upsert(rows, { onConflict: 'extraction_job_id,source_page,reference', ignoreDuplicates: true })` — funciona para rows com reference não-nulo.
