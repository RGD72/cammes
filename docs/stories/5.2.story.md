# Story 5.2 — Exportação de Pedidos em CSV

## Story Statement

As a **admin-distribuidor**,
I want **exportar um pedido individual ou um conjunto filtrado em CSV**,
so that **eu importe no Excel ou empurre para sistemas terceiros**.

## Status

Done

## Context

**Epic:** 5 — Admin Operations, Telemetry & LGPD Compliance
**Previous Story:** 5.1 — Painel de Pedidos (Admin) — Done
**Source:** `docs/prd/6-epic-details.md#story-52`

Story 5.1 implementou o painel de pedidos com lista filtrada, paginação e detalhe por pedido. O botão "Exportar CSV (em breve)" já existe em `app/admin/orders/[id]/page.tsx` como `<button disabled>`. Esta story ativa essa funcionalidade e adiciona exportação da lista filtrada.

### Data Models

interface Order {

  brand_id: string
  customer_user_id: string

```

**OrderItem** (`lib/types/index.ts`) — as 8 colunas do CSV:

interface OrderItem {

  size: string | null       // col 4: Tamanho
  quantity: number          // col 5: Qtd

```

### CSV Format Specification (AC3, AC4)

```
\xEF\xBB\xBF  ← UTF-8 BOM obrigatório para Excel pt-BR
Referência;Descrição;Cor;Tamanho;Qtd;Nome do Cliente;Valor da Peça;Valor Total\r\n
REF-001;Camiseta Branca;Branco;M;2;Maria Silva;89,90;179,80\r\n
```

- Separador: `;`
- Decimal: `,` (não `.`) → `(150.5).toFixed(2).replace('.', ',')`
- Line ending: `\r\n` (compatibilidade Excel Windows)
- Valores nulos/null: string vazia `""`
- Header row: sempre presente

### API Patterns

**CSV Individual** — `app/api/orders/[id]/csv/route.ts`:
```typescript
export async function GET(
  _req: Request,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params
  // 1. auth guard via createServerSupabaseClient() + getUser()
  // 2. getOrder(id) → if !result.ok return 403/404
  // 3. generateCsv(items) → string
  // 4. filename: pedido-{order.order_number}-{YYYY-MM-DD}.csv
  // 5. return new Response(csv, { headers: { 'Content-Type': 'text/csv; charset=utf-8', 'Content-Disposition': `attachment; filename="${filename}"` } })
}
```

**CSV Lista** — `app/api/admin/orders/csv/route.ts`:
```typescript
export async function GET(req: Request) {
  // 1. auth guard
  // 2. parse searchParams → AdminOrderFilters
  // 3. getAdminOrdersForCsv(filters) → Result<AdminOrderRow[]> (cap 1000)
  // 4. para cada row: buscar order_items via supabase
  //    OU: criar query JOIN orders + order_items em uma só chamada
  // 5. flatten items, generateCsv
  // 6. filename: pedidos-{YYYY-MM-DD}.csv
}
```

**Atenção:** Para CSV da lista, a estratégia mais eficiente é uma única query com JOIN:
```sql
SELECT oi.*, o.order_number, o.submitted_at, o.customer_name as order_customer_name
FROM order_items oi
JOIN orders o ON o.id = oi.order_id
WHERE ... (filtros de orders)
ORDER BY o.submitted_at DESC, oi.display_order ASC
LIMIT 1000
```
Via Supabase ORM: `supabase.from('order_items').select('*, orders!inner(*)').eq('orders.brand_id', brandId).limit(1000)`.

### Technical Constraints

- Sem bibliotecas externas para CSV — string manipulation pura é suficiente para MVP.
- Encoding: UTF-8 BOM deve ser prefixado como `Buffer.from('\xEF\xBB\xBF')` ou `'﻿'` + string.
- `Content-Disposition` header: usar `attachment` (forçar download) e não `inline`.
- A rota `/api/admin/orders/csv` usa prefixo `/admin/` para diferenciar de `/api/orders/[id]/csv` (que segue o padrão de rotas do cliente também).

### RLS Notes

- CSV individual: RLS `orders_admin_own_brand` + `order_items_inherit` garantem isolamento. Auth guard `if (!user)` bloqueia não autenticados. Admin só vê seus próprios orders.
- CSV lista: `getAdminOrders` já usa `createServerSupabaseClient()` com RLS ativo — `getAdminOrdersForCsv` segue o mesmo padrão.
