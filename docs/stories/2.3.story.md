## Story

**As a** admin-distribuidor,
**I want** ver, após o upload do PDF, a estimativa de custo da extração (em USD e BRL) baseada no número de páginas detectado e na tarifa do modelo configurado via OpenRouter,
**so that** eu decida com consciência financeira se procedo com a extração.

## Acceptance Criteria

1. Após upload concluído, sistema conta páginas do PDF (server-side via `pdf-lib`) e atualiza `catalogs.page_count`; status do catálogo avança de `pending` para `awaiting_extraction`.
2. Tela `/admin/brands/{id}` exibe card de estimativa quando `catalog.status === 'awaiting_extraction'`: número de páginas, custo estimado USD e custo estimado BRL.
3. Fórmula: `estimatedCostUsd = pages × TOKENS_PER_IMAGE_ESTIMATE × (MODEL_PRICE_USD_PER_1K / 1000)`; câmbio via `BRL_USD_RATE` env var (default `5.80`).
4. Se `estimatedCostBrl > 50`, exige modal de confirmação explícita ("Sim, processar mesmo assim") antes de habilitar botão "Iniciar extração".
5. Botão "Iniciar extração" exibido mas **desabilitado** (com tooltip explicativo) se admin não tiver chave OpenRouter configurada; habilitado quando `hasKey === true`.
6. Cancelamento (fechar estimativa sem confirmar) mantém catálogo em `awaiting_extraction`; admin pode re-fazer upload ou aguardar.
7. Modelo de estimativa documentado em `docs/architecture/cost-estimation-model.md`.

## Complexity Estimate

**T-shirt size: M** (estimativa: 3–5 horas)

Razão: a contagem de páginas com `pdf-lib` é o único componente novo com risco de integração (download do Storage via service role + parsing do PDF). A estimativa de custo é lógica pura testável. A UI é um card simples sem drag-drop.

## Business Value

FR13 — sem estimativa de custo, o admin inicia extração sem previsão financeira, violando NFR21 (controle de custo <R$50/catálogo médio). É pré-requisito imediato para Story 2.4 (o botão "Iniciar extração" desta story alimenta o job da próxima).

## Risks

- **`pdf-lib` em Vercel Serverless:** `pdf-lib` é pure JS sem WASM — sem problemas de binary compatibility. Verificar que o bundle não excede limite de 50MB de Vercel Functions (pdf-lib ~800KB).
- **PDF corrompido ou protegido:** PDFs com senha ou corrompidos falham na leitura do `pdf-lib`. Mitigação: try/catch com graceful fallback (status permanece `pending`, admin vê mensagem de erro, pode re-fazer upload).
- **Tarifa real vs. estimativa:** Preço do Gemini Flash 2.5 via OpenRouter pode variar. Constantes são deliberadamente conservadoras. Documentar que a estimativa é aproximada.
- **Concorrência:** Race condition entre page count e novo upload. Mitigação: verificar `catalog.id` antes de atualizar — usar `eq('id', catalogId)` na query de update.

## Dev Notes

**`pdf-lib` para contagem de páginas (sem conversão)**

`pdf-lib` (`npm install pdf-lib`) é pure TypeScript sem WASM ou dependências nativas — compatível com Vercel Serverless Functions. Para contar páginas:
```typescript
import { PDFDocument } from 'pdf-lib'
const doc = await PDFDocument.load(arrayBuffer, { ignoreEncryption: true })
const pageCount = doc.getPageCount()
```
A opção `ignoreEncryption: true` torna a contagem resiliente a PDFs com senha de leitura (sem senha de edição), que são comuns em catálogos distribuídos.

**Download do PDF do Storage com service role**

A contagem de páginas requer acesso ao conteúdo do arquivo armazenado no bucket privado `catalogs`. O client RLS não tem permissão para download direto (Storage Policy é para upload/select por UI). Usar `createServiceRoleSupabaseClient()` e `.storage.from('catalogs').download(filePath)`.

**Precificação Gemini Flash 2.5 (referência 2026-05)**

Preço via OpenRouter: `$0.0004` per 1K tokens de input para visão (imagem). Estimativa conservadora de `2000 tokens/página` (inclui imagem + texto do prompt de sistema). Catálogo de 100 páginas → estimativa ~`$0.08` = ~`R$ 0.46` — bem abaixo do threshold de R$50. O threshold de R$50 é atingido apenas com catálogos acima de ~10.000 páginas.

**Por que não `model_pricing` DB table?**

MVP: constantes hardcoded + override via env vars é suficiente. A tabela `model_pricing` seria necessária se o admin pudesse configurar múltiplos modelos com preços diferentes e ver comparativos. Para Story 2.4+, se OpenRouter /models API retornar preços, pode-se substituir as constantes sem refactor estrutural (interface `ModelPricing` já está definida).

**`BRL_USD_RATE` env var**

Estabelecida em Story 2.1 (`getMonthlyCost` em `lib/admin/openrouter-settings.ts`). Default `5.80`. Já consta no `.env.local` e Vercel Environment Variables.

**Status `awaiting_extraction` no enum**

`ALTER TYPE ... ADD VALUE IF NOT EXISTS ... BEFORE 'processing'` é DDL irreversível no Postgres (enum values não podem ser removidos sem drop+recreate). Usar `IF NOT EXISTS` para idempotência em re-runs de migration.

**`onExtractConfirmed` placeholder**

O botão "Iniciar extração" em Story 2.3 é um placeholder — a lógica real de criação do `extraction_job` é implementada em Story 2.4. Story 2.3 entrega a UX de confirmação; Story 2.4 conecta ao job. O prop `onExtractConfirmed?: () => void` permite que Story 2.4 injete a lógica sem modificar o componente de estimativa.
