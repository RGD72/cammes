## Story

**As a** admin-distribuidor,
**I want** ser notificado quando um cliente envia um pedido, com badge visível no painel e dropdown com links diretos para os pedidos,
**so that** eu processe cada pedido com a marca rapidamente sem precisar varrer o painel manualmente.

## Acceptance Criteria

1. Badge no header do admin exibe a contagem de notificações não lidas (`admin_notifications.read = false`) para o admin autenticado; contagem 0 oculta o badge.
2. Clique no badge abre dropdown mostrando as últimas 10 notificações não lidas, em ordem decrescente de `created_at`, cada uma com: ícone de tipo, "Novo pedido — {brand_name}" como título, data/hora relativa, e link para `/admin/orders/{order_id}`.
3. Clicar em uma notificação no dropdown marca-a como lida (`read = true` via Server Action) e navega para o link.
4. Botão "Marcar todas como lidas" no rodapé do dropdown executa Server Action que atualiza `read = true` WHERE `admin_user_id = auth.uid()` AND `read = false`.
5. Após marcar como lida (individual ou todas), o badge e a lista do dropdown refletem o novo estado sem recarregar a página inteira (re-fetch via `router.refresh()` ou `startTransition`).
6. Polling automático a cada 30s no client atualiza a contagem do badge enquanto o admin está com o painel aberto.
7. `admin_notifications` são criadas pelo `submitOrder` action (já implementado em Story 4.4) — nenhuma nova lógica de inserção é necessária nesta story.
8. Notificação por e-mail: **fora do escopo MVP** — implementar apenas se Admin habilitar em settings (PRD AC5 — opcional); nesta story, apenas in-app.
9. Acesso restrito via RLS `notif_admin_own` (`admin_user_id = auth.uid()`) — Server Actions devem usar `createServerSupabaseClient` (não service role).

### brand_name via JOIN — Obrigatório para AC2

`AdminNotification` **não tem** campo `brand_name` (apenas `brand_id`). AC2 exige exibir "Novo pedido — {brand_name}".

Solução: usar join Supabase em `getNotifications()`:
```typescript
const { data, error } = await supabase
  .from('admin_notifications')
  .select('*, brands(name)')   // ← JOIN para obter brand name
  .eq('read', false)
  .order('created_at', { ascending: false })
  .limit(10)
```

O resultado terá `brands: { name: string } | null`. Tipar com interseção:
```typescript
type NotificationWithBrand = AdminNotification & { brands: { name: string } | null }
```

No componente: `notification.brands?.name ?? 'Marca'`

### Server Actions — Padrão a Seguir

[Source: lib/orders/actions.ts — padrão estabelecido]

```typescript
'use server'

import { createServerSupabaseClient } from '@/lib/supabase/server'
import type { Result, AdminNotification } from '@/lib/types/index'

export async function getNotifications(): Promise<Result<AdminNotification[]>> {
  const supabase = await createServerSupabaseClient()
  const { data: { user } } = await supabase.auth.getUser()
  if (!user) return permissionDenied()

  const { data, error } = await supabase
    .from('admin_notifications')
    .select('*')
    .eq('read', false)
    .order('created_at', { ascending: false })
    .limit(10)

  if (error) return internalError(error.message)
  return { ok: true, data: (data ?? []) as AdminNotification[] }
}
```

### Hora Relativa — Implementação Simples (sem date-fns)

Para evitar adicionar dependência, implementar manualmente ou usar `Intl.RelativeTimeFormat`:
```typescript
function relativeTime(iso: string): string {
  const diff = Date.now() - new Date(iso).getTime()
  const minutes = Math.floor(diff / 60_000)
  if (minutes < 1) return 'agora'
  if (minutes < 60) return `${minutes}min atrás`
  const hours = Math.floor(minutes / 60)
  if (hours < 24) return `${hours}h atrás`
  return `${Math.floor(hours / 24)}d atrás`
}
```
