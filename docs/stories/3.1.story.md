## Story

**As a** admin-distribuidor,
**I want** uma tela com todos os produtos extraídos do catálogo, em grid editável com foto, referência, descrição, tamanhos, cores e preço, com edição inline campo-a-campo,
**so that** eu corrija e valide rapidamente o que a IA extraiu antes de publicar.

## Acceptance Criteria

1. `/admin/brands/{id}/review` lista todos os produtos com `status='extracted'` em grid responsivo (cards), acessível a partir do detalhe da marca quando `catalog.status = 'ready_for_review'`.
2. Cada card exibe: imagem-recorte (`image_crop_url`) com fallback visual se ausente, referência (`reference`), descrição (`description`), tamanhos como chips (`sizes` jsonb array), cores como chips (`colors` jsonb array), preço (`price_brl`) e badge de confiança derivado de `extraction_confidence` (alta ≥ 0.8, média 0.5–0.79, baixa < 0.5; se `extraction_confidence` for null, omite badge).
3. Clique em qualquer campo editável (referência, descrição, preço) abre edição inline com input/textarea; ao confirmar (Enter ou clique fora), `updateProduct` Server Action persiste a mudança; se a Server Action retornar erro, o campo reverte ao valor original e exibe mensagem de erro discreta.
4. Filtros disponíveis na tela: (a) busca textual por referência ou descrição (debounced 300ms, client-side), (b) por LOOK (`look_group`), (c) por status (extraído / aprovado / oculto), (d) por nível de confiança (baixa primeiro é o default de ordenação).
5. Bulk actions: checkboxes de seleção por card; botões "Aprovar selecionados" (`status → 'approved'`) e "Ocultar selecionados" (`status → 'hidden'`) invocam `bulkUpdateProductStatus` Server Action; re-extração disponível via botão "Reprocessar catálogo" que invoca `retriggerExtraction` (Story 2.6) — não há re-extração por produto individual neste escopo.
6. Indicador de progresso mostra "X aprovados / Y total" no topo; quando `count(status='extracted') = 0` (todos aprovados ou ocultos), exibe mensagem "Revisão completa — todos os produtos foram classificados" e habilita link "Ir para publicação" (que levará para o toggle de publicação da Story 3.3 — link pode ser placeholder nesta story).
7. Server Action `updateProduct(productId, brandId, data)` valida que o produto pertence à marca do admin autenticado antes de persistir; retorna `{ product, error }`.
8. Server Action `bulkUpdateProductStatus(productIds[], brandId, status)` valida pertencimento de todos os IDs à marca; atualiza em batch; retorna `{ updated: number, error }`.
9. Testes unitários para Server Actions: (a) `updateProduct` persiste campo e valida ownership, (b) `updateProduct` retorna erro se produto não pertence à marca, (c) `bulkUpdateProductStatus` atualiza em batch, (d) `bulkUpdateProductStatus` retorna erro se IDs de outra marca forem incluídos.

### Derivação do Badge de Confiança

O campo `extraction_confidence` é um JSONB com score 0-1 por campo. Para o badge, calcular a média dos valores disponíveis:

```typescript
function getConfidenceLevel(confidence: Record<string, number> | null): 'high' | 'medium' | 'low' | null {
  if (!confidence) return null
  const values = Object.values(confidence).filter(v => typeof v === 'number')
  if (values.length === 0) return null
  const avg = values.reduce((a, b) => a + b, 0) / values.length
  if (avg >= 0.8) return 'high'
  if (avg >= 0.5) return 'medium'
  return 'low'
}
```

### Padrão de Server Action (referência)

Seguir padrão de `lib/catalogs/retrigger-actions.ts`:

```typescript
'use server'
import { createServerSupabaseClient } from '@/lib/supabase/server'

export async function updateProduct(
  productId: string,
  brandId: string,
  data: Partial<Pick<Product, 'reference' | 'description' | 'price_brl'>>,
): Promise<{ product: Product | null; error: string | null }> {
  const supabase = await createServerSupabaseClient()
  const { data: { user } } = await supabase.auth.getUser()
  if (!user) return { product: null, error: 'Usuário não autenticado.' }

  // Verificar que o produto pertence à marca do admin autenticado
  const { data: existing } = await supabase
    .from('products')
    .select('id, brand_id')
    .eq('id', productId)
    .eq('brand_id', brandId)
    .single()

  if (!existing) return { product: null, error: 'Produto não encontrado ou acesso negado.' }

  const { data: updated, error } = await supabase
    .from('products')
    .update({ ...data, updated_at: new Date().toISOString() })
    .eq('id', productId)
    .select()
    .single()

  if (error) return { product: null, error: error.message }
  return { product: updated as Product, error: null }
}
```

**Nota:** O cliente do usuário (`createServerSupabaseClient`) herda o RLS de `products_admin_manage` — o admin só consegue operar em produtos de suas marcas. A verificação adicional `.eq('brand_id', brandId)` é defensiva (defense in depth).
