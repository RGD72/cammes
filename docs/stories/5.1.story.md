## Story

**As a** admin-distribuidor,
**I want** ver todos os pedidos em uma lista filtrada por marca, cliente, data e status, com paginação e acesso ao detalhe completo,
**so that** eu opere o pipeline de pedidos sem perder nenhum.

## Acceptance Criteria

1. `/admin/orders` lista pedidos do admin autenticado com colunas: Data, Marca, Cliente, Total (BRL), Status (`received|viewed`), e link "Ver" para o detalhe. Ordenação default: `submitted_at DESC`.
2. Filtros por URL search params (`?brand=&customer=&dateFrom=&dateTo=&status=`): marca (select com marcas do admin), cliente (input texto filtra `customer_name` com ILIKE), data de/até (inputs `date`), status (select: todos | received | viewed). Formulário de filtros é um Client Component que submete como GET — sem JavaScript necessário para submissão básica.
3. Paginação server-side: 25 por página. Parâmetros `?page=1` (default 1). Links "Anterior" / "Próxima" quando aplicável. Exibir "Pedido X–Y de Z total".
4. `/admin/orders/{id}` renderiza detalhe do pedido: cabeçalho com order_number, data, marca, cliente, total; tabela de 8 colunas (Referência, Descrição, Cor, Tamanho, Qtd, Nome do Cliente, Valor da Peça, Valor Total); botão "Baixar PDF" (link para `/api/orders/{id}/pdf` — Story 4.5); botão "Exportar CSV" (fora do escopo desta story — renderiza desabilitado com label "Em breve").
5. Toggle "Marcar como visto" na página `/admin/orders/{id}`: exibe status atual; quando `received`, botão ativo "Marcar como visto" executa Server Action que atualiza `status = 'viewed'` e `viewed_at = now()`; quando `viewed`, exibe badge "Visto" sem botão.
6. `getAdminOrders` usa `createServerSupabaseClient()` (RLS `orders_admin_own_brand`): admin vê apenas pedidos de suas próprias marcas. Nenhum filtro de `admin_user_id` explícito no código — RLS garante isolamento.
7. Testes unitários cobrem: listagem com filtros, paginação, e Server Action `markOrderViewed`.

## Dev Notes

### Padrão de Filtragem via URL (Next.js 15 App Router)

O componente de filtros submete como GET — sem `useState` para os filtros, o estado vive na URL. O Server Component lê `searchParams` e repassa para `getAdminOrders`.

```typescript
// app/admin/orders/page.tsx (simplificado)
export default async function AdminOrdersPage({
  searchParams,
}: {
  searchParams: Promise<{ brand?: string; customer?: string; status?: string; page?: string }>
}) {
  const params = await searchParams
  const page = Math.max(1, Number(params.page ?? 1))
  const filters: AdminOrderFilters = {
    brandId: params.brand || undefined,
    customerName: params.customer || undefined,
    status: (params.status as OrderStatus) || undefined,
  }
  const result = await getAdminOrders(filters, page)
  // ...
}
```

### getAdminOrders — JOIN brands para brand_name

O campo `brand_name` não existe em `orders` — obter via JOIN Supabase:

```typescript
const { data, count, error } = await supabase
  .from('orders')
  .select('*, brands(name)', { count: 'exact' })
  .order('submitted_at', { ascending: false })
  .range((page - 1) * 25, page * 25 - 1)
  // filtros condicionais aplicados com .eq() / .ilike() / .gte() / .lte()
```

Tipo de retorno (interseção):
```typescript
type AdminOrderRow = Order & { brands: { name: string } | null }
```

### Filtros Condicionais

```typescript
let query = supabase
  .from('orders')
  .select('*, brands(name)', { count: 'exact' })
  .order('submitted_at', { ascending: false })
  .range((page - 1) * PAGE_SIZE, page * PAGE_SIZE - 1)

if (filters.brandId) query = query.eq('brand_id', filters.brandId)
if (filters.customerName) query = query.ilike('customer_name', `%${filters.customerName}%`)
if (filters.dateFrom) query = query.gte('submitted_at', filters.dateFrom)
if (filters.dateTo) query = query.lte('submitted_at', filters.dateTo + 'T23:59:59Z')
if (filters.status) query = query.eq('status', filters.status)
```

### markOrderViewed — Nota de Segurança

A RLS `orders_admin_own_brand` cobre UPDATE também (`FOR ALL`). Portanto:

```typescript
const { error } = await supabase
  .from('orders')
  .update({ status: 'viewed', viewed_at: new Date().toISOString() })
  .eq('id', orderId)
```

Nenhum WHERE adicional com `admin_user_id` necessário — RLS garante que admin só pode atualizar pedidos de suas marcas.

### brand_name na página de detalhe

`Order` não tem `brand_name`. Para exibir o nome da marca no cabeçalho do detalhe, duas opções:
1. Fazer segundo SELECT de `brands` após `getOrder` (simples, recomendado no MVP)
2. Criar `getOrderWithBrand()` que faz JOIN — overkill para MVP

Recomendado: `const { data: brand } = await supabase.from('brands').select('name').eq('id', order.brand_id).single()`

### Formatação de Data

Seguir padrão de `lib/pdf/order-pdf.tsx` (Story 4.5): `dd/MM/yyyy HH:mm` sem dependência de date-fns:

```typescript
function formatDate(iso: string): string {
  const d = new Date(iso)
  const pad = (n: number) => String(n).padStart(2, '0')
  return `${pad(d.getDate())}/${pad(d.getMonth() + 1)}/${d.getFullYear()} ${pad(d.getHours())}:${pad(d.getMinutes())}`
}
```
