## Story

**As a** lojista-cliente,
**I want** acessar a plataforma pela primeira vez por um magic link recebido por e-mail e recuperar minha senha quando esquecer,
**so that** o onboarding seja livre de atrito e eu não fique bloqueado da plataforma.

## Acceptance Criteria

1. Admin pode (via Supabase Studio ou CLI no MVP) enviar magic link para um cliente cadastrado; o link autentica o usuário e o redireciona para `/brands`.
2. Rota `GET /auth/callback` troca o `code` de autorização por uma sessão Supabase válida e redireciona para a área correta conforme `role` (`admin → /admin`, `customer → /brands`).
3. Página `/recover-password` permite ao usuário informar o e-mail cadastrado e solicitar o link de redefinição de senha; exibe mensagem de confirmação após envio (sem revelar se o e-mail existe ou não).
4. Link de reset abre a tela `/reset-password`; formulário exige nova senha (>=8 caracteres) e confirmação; exibe mensagens de validação inline por campo antes de submeter.
5. Após redefinição bem-sucedida, sessão é encerrada e usuário é redirecionado para `/login` com mensagem de sucesso.
6. Validação inline por campo implementada no formulário `/login` (carry-forward de AC1-001 da Story 1.3): "E-mail inválido" abaixo do campo de e-mail sem aguardar resposta do servidor.
7. `id="form-error"` adicionado ao div de erro em `login-form.tsx` corrigindo referência ARIA quebrada (carry-forward de A11Y-001 da Story 1.3).

## Complexity Estimate

**T-shirt size: S** (estimativa: 2–3 horas)

Razão: infraestrutura de auth já existe (Story 1.3). Esta story adiciona 1 rota de callback, 2 novas páginas com forms simples e 2 Server Actions. Supabase fornece `signInWithOtp` e `resetPasswordForEmail` out-of-the-box. Os fixes carry-forward (A11Y-001, AC1-001) são cirúrgicos — 1 atributo `id` e validação HTML5 + mensagem customizada.

## Business Value

Habilita o onboarding sem fricção — clientes recebem magic link via admin e acessam a plataforma sem criar senha. A recuperação de senha elimina o principal motivo de abandono de plataformas B2B. Story 1.5 (dashboards funcionais) e Epic 5 (gestão de acessos) dependem desta story estar funcional.

## Risks

- **Supabase SMTP em desenvolvimento:** Por padrão, Supabase local não envia e-mails reais — usar Inbucket (embutido no CLI) em `http://127.0.0.1:54324` para capturar e-mails de teste. Documentar URL no Dev Notes.
- **Redirect URL de reset:** `resetPasswordForEmail` requer `redirectTo` configurado nos Allowed Redirect URLs do projeto Supabase; falhas silenciosas se não configurado.
- **Token de reset no hash da URL:** Supabase envia o token no fragmento `#access_token=...&type=recovery`; o callback route precisa lidar com o fluxo PKCE corretamente — `exchangeCodeForSession` trata isso quando `type=recovery`.
- **Sessão ativa pós-reset:** Após `updateUser({ password })`, a sessão do usuário permanece ativa. Por segurança, chamar `signOut()` antes do redirect para `/login`.

### Supabase Magic Link — Como Funciona no MVP

No MVP, o admin envia o magic link via Supabase Studio:
1. Supabase Studio → Authentication → Users → selecionar usuário → "Send magic link"
2. Ou via CLI: `supabase auth invite <email>` (cria usuário + envia link)

O link gerado aponta para `/auth/callback?code=<code>`. A rota de callback troca o code por sessão e redireciona pelo role.

> **Nota:** UI de envio de magic link pelo admin fica na Story 5.3 (Gestão de Acessos).

### Rota de Callback: Padrão PKCE Supabase

```typescript
// app/auth/callback/route.ts
import { NextRequest, NextResponse } from 'next/server'
import { createServerSupabaseClient } from '@/lib/supabase/server'

export async function GET(request: NextRequest) {
  const { searchParams, origin } = new URL(request.url)
  const code = searchParams.get('code')
  const next = searchParams.get('next') ?? '/brands'

  if (!code) {
    return NextResponse.redirect(`${origin}/login?error=auth_callback_failed`)
  }

  const supabase = await createServerSupabaseClient()
  const { error } = await supabase.auth.exchangeCodeForSession(code)

  if (error) {
    return NextResponse.redirect(`${origin}/login?error=auth_callback_failed`)
  }

  // Ler role para redirect correto (reusa padrão da loginAction)
  const { data: { user } } = await supabase.auth.getUser()
  if (user) {
    const { data: profile } = await supabase
      .from('users_profile')
      .select('role')
      .eq('id', user.id)
      .single()

    if (profile?.role === 'admin') {
      return NextResponse.redirect(`${origin}/admin`)
    }
  }

  // customer ou next especificado (reset-password)
  return NextResponse.redirect(`${origin}${next}`)
}
```

> [Source: Supabase PKCE flow docs; `@supabase/ssr ^0.5.x`]

### Password Recovery: Anti-Enumeration

`requestPasswordResetAction` deve sempre retornar a mesma mensagem de sucesso, independente de o e-mail existir no sistema. Isso previne que atacantes descubram quais e-mails estão cadastrados.

```typescript
// lib/auth/actions.ts (adição)
export async function requestPasswordResetAction(
  _prevState: unknown,
  formData: FormData
): Promise<{ error?: string; success?: string }> {
  const email = formData.get('email') as string
  const headersList = await headers()
  const origin = headersList.get('origin') ?? ''

  const supabase = await createServerSupabaseClient()
  await supabase.auth.resetPasswordForEmail(email, {
    redirectTo: `${origin}/auth/callback?next=/reset-password`,
  })

  // Sempre retorna sucesso — não revela se e-mail existe
  return { success: 'Se esse e-mail estiver cadastrado, você receberá um link em breve.' }
}
```

### Update Password: Sign Out Pós-Reset

Após `updateUser({ password })` com sucesso, encerrar a sessão antes do redirect. Isso força o usuário a fazer login com a nova senha, confirmando que o fluxo funciona ponta a ponta.

```typescript
export async function updatePasswordAction(
  _prevState: unknown,
  formData: FormData
): Promise<{ error?: string }> {
  const password = formData.get('password') as string
  const confirmPassword = formData.get('confirmPassword') as string

  if (password.length < 8) {
    return { error: 'Senha deve ter no mínimo 8 caracteres.' }
  }
  if (password !== confirmPassword) {
    return { error: 'As senhas não coincidem.' }
  }

  const supabase = await createServerSupabaseClient()
  const { error } = await supabase.auth.updateUser({ password })

  if (error) {
    return { error: 'Erro ao redefinir senha. O link pode ter expirado.' }
  }

  await supabase.auth.signOut()
  redirect('/login?message=password_updated')
}
```

### Validação Inline por Campo (Fix AC1-001)

Padrão recomendado para o login form sem `useFormStatus`:

```tsx
// login-form.tsx — adicionar estado local por campo
const [emailError, setEmailError] = useState<string>('')

const validateEmail = (value: string) => {
  if (!value) { setEmailError(''); return }
  const valid = /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value)
  setEmailError(valid ? '' : 'E-mail inválido')
}

// No JSX:
<input
  id="email"
  type="email"
  name="email"
  onChange={(e) => validateEmail(e.target.value)}
  aria-describedby={emailError ? 'email-error' : undefined}
/>
{emailError && <p id="email-error" className="text-sm text-red-600">{emailError}</p>}
```
