# Story 5.8 — Telemetria de KPIs do MVP (Eventos de Produto)

## Story Statement

**As a** PM / stakeholder,
**I want** eventos server-side que permitam calcular os KPIs do MVP (TMCV, TPE, PEE, CME, ABS, CtO, AAD) sem depender de Google Analytics,
**so that** o sucesso do MVP seja mensurável desde o dia 1 (NFR31 + Goals do brief).

## Status

Done

## Context

**Epic:** 5 — Admin Operations, Telemetry & LGPD Compliance
**Previous Story:** 5.7 — Direito ao Esquecimento (Exclusão de Conta sob Requisição) — Done
**Source:** `docs/prd/6-epic-details.md#story-58`

Esta é a última story do Epic 5 e do MVP. Ela completa a camada de observabilidade ao expor um dashboard admin com os 7 KPIs do Project Brief, calculados exclusivamente a partir de dados já persistidos no Supabase (sem dependência de ferramentas externas de analytics).

**Estado atual da instrumentação (`lib/audit/log-event.ts`):**

Os seguintes eventos já são registrados em `audit_logs`:
- `login_success` — base para AAD (KPI-7)
- `order_submitted` — base para PEE (KPI-3) e denominador CtO (KPI-6)
- `brand_published` — base indireta para ABS (KPI-5)
- `extraction_started`, `extraction_completed`, `extraction_failed` — base para TMCV e CME via `extraction_jobs`

**Lacuna identificada:** O evento `cart_item_added` não existe. Ele é necessário para o **numerador do CtO (KPI-6)**: _"sessões de cliente com produto adicionado"_. O `addItem()` em `lib/carts/actions.ts` ainda não chama `logAuditEvent`.

**Abordagem TPE (KPI-2):** A Taxa de Precisão da Extração não é calculável automaticamente sem comparação manual com o PDF original. Para o MVP, o TPE é aproximado pelo ratio `approved products / total extracted products` na tabela `products`. Isso deve ser documentado claramente no `kpi-mapping.md` e na UI.

**Abordagem ABS (KPI-5):** _Active Brand Stores_ = marcas com `published = true` que receberam >=1 pedido nos últimos 30 dias. Calculado diretamente via JOIN entre `brands` e `orders`.

**Caching:** Queries de KPI são pesadas. A página `/admin/reports/kpis` deve revalidar com `revalidate = 60` (cache server-side de 60s) conforme especificado no PRD Epic 5.4 AC5.

**Nenhuma tabela nova é necessária:** Todos os KPIs usam dados já existentes em `audit_logs`, `extraction_jobs`, `orders`, `brands` e `products`. Nenhuma migração Supabase é necessária nesta story.

### Atenção: `getTpe()` é uma aproximação

A TPE real requer comparação manual produto-a-produto com o PDF original (processo trabalhoso). Para o MVP, usamos:

```sql
SELECT
  COUNT(*) FILTER (WHERE status = 'approved') * 100.0
  / NULLIF(COUNT(*) FILTER (WHERE status IN ('approved', 'extracted', 'hidden')), 0)
FROM products
-- sem filtro temporal: acumulado total
```

Isso mede _"qual % dos produtos extraídos foi aprovado pelo admin"_ — proxy razoável para TPE no MVP, pois admin hidding/rejecting = extração ruim. Deve ser exibido com disclaimer visual claro.
