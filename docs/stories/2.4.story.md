## Story

**As a** admin-distribuidor,
**I want** que, ao iniciar a extração, o sistema processe o PDF em background e me informe o progresso, sem travar minha tela,
**so that** eu possa continuar trabalhando enquanto a IA cadastra os produtos.

## Acceptance Criteria

1. Ao clicar "Iniciar extração" (com ou sem modal de confirmação, conforme Story 2.3), o sistema cria registro em `extraction_jobs` com `status = 'queued'`, atualiza `catalogs.status = 'processing'` e aciona a Supabase Edge Function `extract-catalog` via chamada HTTP a partir de Server Action; admin é redirecionado para `/admin/brands/{id}/extraction/{jobId}`.
2. Pipeline na Edge Function: baixa PDF do Storage via service role, converte cada página em PNG (resolução configurável, default 1024px largura via `pdfjs-dist` no ambiente Deno), envia ao modelo OpenRouter configurado com prompt estruturado documentado em `docs/architecture/extraction-prompt.md`; chave OpenRouter é passada pela Server Action via header de invocação e nunca persiste em logs.
3. Resposta JSON de cada página é validada contra schema Zod (`ZodExtractionResult`); produtos válidos são persistidos em `products` com `brand_id`, `catalog_id`, `extraction_job_id`, `source_page` e `extraction_confidence` por campo; itens com JSON inválido são contabilizados em `error_message` mas não interrompem o processamento das demais páginas.
4. A cada página processada, a Edge Function atualiza `extraction_jobs.pages_processed`, `products_count` e `actual_cost_usd` (calculado de `usage.prompt_tokens + usage.completion_tokens` × tarifa do modelo) via Supabase client com service role.
5. Tela de progresso `/admin/brands/{id}/extraction/{jobId}` exibe: badge de status (`queued` / `running` / `done` / `failed`), barra de progresso `pages_processed / pages_total`, contagem parcial de produtos cadastrados e custo real acumulado (USD e BRL); atualizada em tempo real via Supabase Realtime (subscription em `extraction_jobs` WHERE `id = eq.{jobId}`) sem reload manual.
6. Em caso de falha em chamada ao OpenRouter (timeout, 5xx, rate limit), a Edge Function aplica retry exponencial até 3x por chamada (delays: 2s, 4s, 8s); após exaustão de todas as tentativas, `extraction_jobs.status = 'failed'` com `error_message` descritivo e `catalogs.status` permanece `processing` (admin pode re-disparar via Story 2.6).
7. Extração concluída com sucesso: `extraction_jobs.status = 'done'`, `completed_at` preenchido, `catalogs.status = 'ready_for_review'`; tela de progresso exibe botão "Revisar produtos" com link para `/admin/brands/{id}/review` (Story 3.1 — botão visível mas desabilitado com tooltip "Funcionalidade disponível em breve").
8. Custo real final registrado em `extraction_jobs.actual_cost_usd` e `actual_cost_brl` (usando `BRL_USD_RATE` env var, default `5.80`) para consulta na tela de gestão OpenRouter (Story 2.1 AC5).

## Risks

- **`pdfjs-dist` em Deno Edge Function**: `pdfjs-dist` é compatível com ambientes sem DOM mas pode ter incompatibilidades com a sandbox Deno da Supabase (especialmente `OffscreenCanvas`). Verificar disponibilidade em `supabase functions serve` antes de implementar. Fallback: enviar o PDF inteiro como base64 ao OpenRouter (se o modelo suportar) em vez de converter página por página.
- **Edge Function timeout (60s)**: catálogos com muitas páginas podem exceder o timeout padrão. Mitigação: usar `--max-duration 150` no deploy e processar em blocos; para MVP, limitar a catálogos de até 50 páginas (NFR4).
- **OpenRouter rate limits**: Gemini Flash 2.5 tem limites RPM. Com catálogos grandes, o pipeline pode atingir o limite antes de concluir. Mitigação: retry com backoff + `min_delay_between_pages` configurável (default 1s).
- **Tamanho do PNG base64**: imagens PNG 1024px de catálogos densos podem ter 1-3MB, chegando a 4MB em base64. OpenRouter aceita mas latência aumenta. Mitigação: ajustar resolução ou compressão se necessário.
- **Decriptografia da chave OpenRouter na Edge Function**: a Edge Function precisa da chave em texto claro para chamar o OpenRouter. A abordagem MVP — passar via header de invocação da Server Action — é aceitável pois a chamada é protegida por `SUPABASE_SERVICE_ROLE_KEY` e não persiste a chave. Documentar explicitamente no código e no prompt de extração.
- **Variáveis de ambiente em Edge Functions locais**: `SUPABASE_SERVICE_ROLE_KEY` e outras env vars devem ser configuradas em `supabase/functions/.env` para `supabase functions serve`. Não confundir com `.env.local` do Next.js.

### Supabase Edge Functions (Deno) — Invocação Assíncrona

Edge Functions da Supabase rodam em Deno. Para não bloquear a resposta HTTP enquanto processa o PDF:

```typescript

Deno.serve(async (req) => {
  const payload = await req.json()

  const responsePromise = EdgeRuntime.waitUntil(processExtraction(payload))
  
  return new Response(JSON.stringify({ status: 'accepted' }), {
    headers: { 'Content-Type': 'application/json' },
```

### `pdfjs-dist` em Deno

Importar via `npm:` specifier (Deno 1.28+):
```typescript
import * as pdfjs from 'npm:pdfjs-dist@4'
```

Renderizar uma página como PNG com `OffscreenCanvas`:
```typescript
const doc = await pdfjs.getDocument({ data: pdfArrayBuffer }).promise
const page = await doc.getPage(pageIndex) // 1-indexed
const viewport = page.getViewport({ scale: 1024 / page.getViewport({ scale: 1 }).width })
const canvas = new OffscreenCanvas(Math.floor(viewport.width), Math.floor(viewport.height))
const ctx = canvas.getContext('2d')
await page.render({ canvasContext: ctx as unknown as CanvasRenderingContext2D, viewport }).promise
const blob = await canvas.convertToBlob({ type: 'image/png' })
const base64 = btoa(String.fromCharCode(...new Uint8Array(await blob.arrayBuffer())))
```

### Retry Exponencial

```typescript
async function withRetry<T>(fn: () => Promise<T>, maxRetries = 3): Promise<T> {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    try {
      return await fn()
    } catch (err) {
      if (attempt === maxRetries - 1) throw err
      await new Promise(resolve => setTimeout(resolve, Math.pow(2, attempt) * 2000))
    }
  }
  throw new Error('Max retries exceeded')
}
```

### Decriptografia da Chave OpenRouter

A Edge Function recebe a chave decriptada via header `X-OpenRouter-Key` (passado pela Server Action). A Server Action tem acesso ao `OPENROUTER_KEY_ENCRYPTION_SECRET` via `process.env`.

**Padrão real de decriptação** (verificado em `lib/admin/openrouter-settings.ts:5,79`):

```typescript
import { decryptKey } from '@/lib/openrouter/crypto'
import { createServiceRoleSupabaseClient } from '@/lib/supabase/admin'

// Dentro de startExtractionJob():
const supabase = createServiceRoleSupabaseClient()
const { data } = await supabase
  .from('admin_settings')
  .select('openrouter_key_encrypted, openrouter_model')
  .eq('admin_user_id', adminId)
  .single()

const openrouterKey = await decryptKey(data.openrouter_key_encrypted)
const modelId = data.openrouter_model ?? 'google/gemini-flash-2.5'
```

Não existe função `getDecryptedOpenRouterKey()` — usar diretamente `decryptKey` de `@/lib/openrouter/crypto` conforme o padrão de Story 2.1.
