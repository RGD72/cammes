# Story 5.5 — Log de Auditoria e Eventos de Produto

## Story Statement

**As a** engenheiro de qualidade / admin,
**I want** uma tabela `audit_logs` que registre eventos críticos com user_id, event_type, target_resource, payload e timestamp, com página de consulta filtrável e exportação CSV,
**so that** incidentes possam ser investigados e a operação esteja em conformidade com NFR16 (retenção 90 dias) e FR38 (audit-by-default).

### Schema `audit_logs` (CRÍTICO)
`[Source: architecture.md#9 — DDL]`

```sql
-- supabase/migrations/20260526000001_audit_logs.sql
CREATE TABLE audit_logs (
  id BIGSERIAL PRIMARY KEY,
  user_id UUID REFERENCES users_profile(id) ON DELETE SET NULL,
  event_type TEXT NOT NULL,
  target_resource_type TEXT,
  target_resource_id TEXT,
  payload JSONB NOT NULL DEFAULT '{}'::jsonb,
  ip_address INET,
  user_agent TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_audit_user_created ON audit_logs(user_id, created_at DESC);
CREATE INDEX idx_audit_event_created ON audit_logs(event_type, created_at DESC);

ALTER TABLE audit_logs ENABLE ROW LEVEL SECURITY;
CREATE POLICY audit_admin_read ON audit_logs
  FOR SELECT USING (
    EXISTS (SELECT 1 FROM users_profile WHERE id = auth.uid() AND role = 'admin')
  );
-- Inserts via service_role server-side; sem policy de INSERT user-facing.
```

**Importante:** `user_id` é `NULL` para eventos pré-autenticação (`login_failed`). `ON DELETE SET NULL` preserva o log mesmo se o usuário for deletado.

### `logAuditEvent` — Implementação Real
`[Source: architecture.md#6.6 — audit-logger]`

```typescript
// lib/audit/log-event.ts
'use server'

import { createServiceRoleSupabaseClient } from '@/lib/supabase/admin'
import { headers } from 'next/headers'

export type AuditEventType =
  | 'login_success'
  | 'login_failed'
  | 'logout'
  | 'openrouter_key_updated'
  | 'brand_published'
  | 'brand_unpublished'
  | 'extraction_started'
  | 'extraction_completed'
  | 'extraction_failed'
  | 'order_submitted'
  | 'order_viewed'
  | 'customer_invited'
  | 'customer_brand_granted'
  | 'customer_brand_revoked'
  | 'customer_deactivated'
  | 'pdf_downloaded'
  | string  // extensível para novos eventos

export async function logAuditEvent(
  eventType: AuditEventType,
  payload: Record<string, unknown>,
): Promise<void> {
  try {
    let ipAddress: string | null = null
    let userAgent: string | null = null
    try {
      const h = await headers()
      ipAddress =
        h.get('x-forwarded-for')?.split(',')[0]?.trim() ??
        h.get('x-real-ip') ??
        null
      userAgent = h.get('user-agent') ?? null
    } catch {
      // headers() indisponível fora de contexto de request
    }

    const supabase = createServiceRoleSupabaseClient()
    const userId = (payload.userId as string | undefined) ?? null

    await supabase.from('audit_logs').insert({
      event_type: eventType,
      user_id: userId,
      payload,
      ip_address: ipAddress,
      user_agent: userAgent,
    })
  } catch {
    // auditoria NUNCA bloqueia o fluxo principal
  }
}
```

**Nota sobre `user_id`:** O `user_id` é extraído do `payload.userId` por convenção — todos os callers existentes passam `{ userId: user.id, ... }` ou payload sem userId (eventos pré-auth). Se necessário, os callers podem ser atualizados para passar `userId` explicitamente — sem mudança na assinatura pública.

### RLS e Segurança
`[Source: architecture.md#2.5 — RLS-as-Authorization; architecture.md#12 — Security]`

- **INSERT:** service_role bypass (não há policy de INSERT — inserts vêm de Server Actions server-side)
- **SELECT:** apenas admins autenticados via `audit_admin_read` policy
- **Clients não têm acesso a nenhuma linha** — sem `user_has_brand_access` nesta tabela
- **Dados sensíveis no payload:** payload é JSONB livre — evitar logar senhas ou chaves; os callers existentes já só passam IDs e tipos

### Limitação Documentada (fora do escopo)
Eventos `extraction_started`, `extraction_completed`, `extraction_failed` são disparados pela **Edge Function Deno** (`supabase/functions/extraction-pipeline/`), não por Server Actions Node.js. O helper `logAuditEvent` de Node não é acessível no contexto Deno. Esses eventos precisam ser logados diretamente na Edge Function usando o Supabase client Deno com service_role — escopo da Story 5.8 ou task de manutenção futura.
