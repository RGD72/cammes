## Story

**As a** lojista-cliente,
**I want** uma página `/brands/[slug]/cart` (ou `/cart/[brand_slug]`) que mostre meu carrinho como tabela com as 8 colunas obrigatórias, com edição inline de quantidade, remoção por linha e linha de total,
**so that** eu confira o que pedi exatamente no formato que será enviado, com total transparência sobre preços e identidade do cliente.

## Acceptance Criteria

1. Tabela com colunas, **na ordem exata**: REFERÊNCIA, DESCRIÇÃO DO PRODUTO, COR, TAMANHO, QUANTIDADE, NOME DO CLIENTE, VALOR DA PEÇA, VALOR TOTAL.
2. Cada item é uma linha; produtos de mesmo LOOK aparecem em linhas separadas (FR24 — sem agrupamento visual).
3. Quantidade editável inline com stepper +/− por linha, atualizando VALOR TOTAL da linha automaticamente via `useOptimistic` (React 19).
4. Botão remover por linha; botão "Limpar carrinho" no topo da página.
5. Campo NOME DO CLIENTE: editor global no topo do carrinho, pré-preenchido com nome do usuário logado, editável e propagado para todas as linhas ao salvar (`setCustomerName`); Server Action persiste o valor.
6. Linha "Total Geral" fixa no rodapé da tabela com soma de VALOR TOTAL de todos os itens.
7. Em mobile (< 768px), tabela alterna para layout de cards empilhados — cada item como bloco chave-valor preservando os 8 campos.
8. Estado vazio: componente `EmptyState` com mensagem "Seu carrinho está vazio. Volte à vitrine e escolha produtos." e botão/link "Ver vitrine".

## Complexity

**Médio** — 3 pontos

Frontend com estado compartilhado entre RSC (fetch de dados) e Client Components (interações). Complexidade concentrada em: (a) `useOptimistic` para edição de quantidade sem flicker, (b) layout responsivo de tabela → cards, (c) NOME DO CLIENTE global com propagação.

## Business Value

Sem esta story, o cliente não tem visibilidade do carrinho e não pode revisar ou corrigir o pedido antes de enviar. É o pré-requisito direto de Story 4.4 (envio do pedido) e fecha o ciclo visual do fluxo ESCOLHER → carrinho → revisão → envio.

## Risks

- **`useOptimistic` com rollback:** Se `updateQuantity` falhar, o estado otimista deve reverter para o valor original. Implementar rollback explícito no catch da Server Action.
- **`brand_slug → brand_id` resolve:** A rota `/cart/[brand_slug]` precisa resolver o slug para o `brand_id` antes de chamar `getCart`. Fazer SELECT `brands WHERE slug = brand_slug` no início do RSC.
- **`setCustomerName` nova Action:** Não existe ainda em `lib/carts/actions.ts`. Implementar UPDATE em `carts SET customer_name = $name WHERE user_id = auth.uid() AND brand_id = $brandId`.
- **Tabela responsiva:** shadcn/ui Table não tem responsive mode nativo. Implementar alternância via Tailwind (`hidden md:table` / `block md:hidden`) com dois layouts: tabela para desktop, cards para mobile.
